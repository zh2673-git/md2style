# md2style 架构设计

## 架构图（第0级映射坐标系）

```
┌──────────────────────────────────────────────────────────────────┐
│  数据接口层  interfaces                                                │
│  ┌─────────────────────────┐   ┌──────────────────────────────────┐ │
│  │ md2style/cli.py (argparse)│   │ md2style/interfaces/web/ (纯Python) │ │
│  │ convert/learn/preview     │   │ 本地Web服务, 浏览器表单入口        │ │
│  │ (人/LLM 固定入口)         │   │ (普通用户可视化入口, 不打包exe)    │ │
│  └────────────┬────────────┘   └───────────────┬──────────────────┘ │
└───────────────┼─────────────────────────────────┼────────────────────┘
                │ 依赖                              │ 依赖
┌───────────────▼─────────────────────────────────▼──────────────────┐
│  数据流转(编排) application → md2style/orchestrator.py               │
│  子命令路由 + 参数白名单校验 + 流程编排                               │
└───────┬───────────────────┬───────────────────┬─────────────────┘
        │ 依赖(接口)         │ 依赖(接口)         │ 依赖(接口)
┌───────▼────────┐  ┌────────▼─────────┐  ┌──────▼──────────────┐
│ 数据流转(规则)  │  │ 数据流转(规则)    │  │ 数据流转(规则)       │
│ domain/engines │  │ domain/engines   │  │ domain/engines      │
│ Style Engine   │  │ MD Parser        │  │ Learner             │
└───────┬────────┘  └────────┬─────────┘  └──────┬──────────────┘
        │ 依赖抽象            │ 依赖抽象          │ 依赖抽象
┌───────▼────────────────────▼──────────────────▼──────────────────┐
│  数据接口(渲染) renderers/  →  Docx / Html / Ppt Renderer (base)  │
└───────────────────────────────┬──────────────────────────────────┘
                                 │ 依赖抽象
┌───────────────────────────────▼──────────────────────────────────┐
│  数据规范 core/  →  IR 定义 / 常量 / 错误码                       │
│  数据存储 infrastructure/ → styles/*.yaml, templates/, 字体探测   │
└──────────────────────────────────────────────────────────────────┘

依赖方向铁律：cli / web → orchestrator → engines/renderers → core；
              engines/renderers → infrastructure(抽象) ；infrastructure 绝不反向依赖 domain。
              web 界面层仅采集参数与展示结果，不含业务规则。
```

## 第0级物理目录映射
| 标准四层 | 物理目录 | 职责 |
|----------|---------|------|
| 数据规范 | `md2style/core/` | IR 节点类型、全局常量、错误码、日志配置 |
| 数据存储 | `styles/`、`templates/`、`md2style/utils/fonts.py` | YAML 预设、dotx/html 模板、系统字体探测 |
| 数据流转(规则) | `md2style/engines/` | style_engine / md_parser / learner |
| 数据流转(编排) | `md2style/orchestrator.py` | 子命令路由、白名单、流程 |
| 数据接口 | `md2style/cli.py` + `md2style/interfaces/web/` + `md2style/renderers/` | CLI 入口 + 本地 Web 界面 + 渲染执行器族 |

## 技术选型理由（由本质推导）
| 用途 | 选型 | 推导逻辑 |
|------|------|---------|
| CLI 框架 | `argparse` | 签名稳定可解析 → 满足"参数白名单护栏"本质 |
| MD 解析 | `markdown-it-py` | 标准 AST → 满足"统一语义 IR"本质 |
| Word | `python-docx` | 样式读写双向 → 同时满足 convert 与 learn |
| HTML | `Jinja2` + `Pygments` | 自包含 CSS 变量注入 + 代码高亮 |
| PPT | `python-pptx` | 母版主题色修改 |
| 配置 | `PyYAML` | 声明式、人/LLM 共读 |
| 包管理 | `Poetry` | 锁定版本保障固定脚本稳定 |
| Web 界面 | `PyWebIO` 或 `Streamlit` | 纯 Python 本地服务，普通用户可视化入口，避免 exe 打包不稳定 |
| 预设库 | `paper/official/claude/mac` YAML | 开箱即用风格；用户"学习"生成的样式与之同目录、同等可选 |

## 关键设计决策
1. **IR 中间表示**：所有渲染器共享同一 IR，新增格式零改动解析链路（扩展性本质）。
2. **参数白名单**：Orchestrator 在入口拦截未知参数，错误即退出并提示正确列表——LLM 无幻觉的核心护栏。
3. **样式三层合并**：DEFAULT(硬编码) < YAML < CLI 覆盖，后者覆盖前者，结果经 validate 才生效。
4. **渲染器抽象基类**：`base.py` 定义 `render(ir, final_style, output_path)`，新增 pdf/latex 只需继承。
5. **Learner 双模式**：精准读标准样式 + 启发式聚类兜底，输出结构与 StyleConfig 同构，保证闭环互通。
