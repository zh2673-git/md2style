# md2style 项目方案

## 项目目标
md2style 解决"同一份 Markdown 内容需要以多种固定版式（Word / HTML / PPT）交付，且版式要能被人类和 LLM 稳定复用"的痛点。它提供**统一的 CLI + 本地 Web 界面双入口**，让人和 LLM 都能完成两类任务：
1. **转换**：Markdown → docx / html / pptx，样式由后端 YAML 预设 + CLI/表单微调固定控制。
2. **学习样式（一等公民）**：用户看到心仪的 Word/版式模板，拖入即被逆向提取为可复用 YAML 预设，**立刻出现在风格下拉框中可供选用**——这是产品最核心的黏性与价值点。

预定义风格资产（开箱即用）：
- **docx**：`论文风格`（学术排版：章节编号、宋体/ Times、固定行距）、`公文风格`（红头/仿宋、标题居中、特定页边距）。
- **html**：`claude风格`（Anthropic 官网观感：克制留白、衬线标题、柔和分割线）、`mac风格`（系统原生感：圆角卡片、SF 字体栈、毛玻璃质感）。
- **ppt**：复用对应 html 风格（即 `claude风格` / `mac风格` 各一套母版）。

所有样式逻辑由后端固定脚本裁决，LLM 只能传参、不能生成代码，从机制上杜绝版式"幻觉"。

## 本质定义
md2style 的本质是**用「声明式样式表（YAML）+ 参数白名单」取代「对版式的自由文本描述」**，把"你帮我排好看点"这类不可执行意图，转化为"按固定映射把语义 AST 节点写入目标格式的版式引擎"。

> 本质检验：该定义能解释所有其它属性——
> - 为何需要 YAML 预设库？因为样式必须"声明式、可复用"。
> - 为何要 CLI 覆盖 + 白名单校验？因为 LLM/人只能"填参数"，不能"编逻辑"。
> - 为何要 IR（中间表示）？因为多格式共享同一份语义，剥离原样式后才能统一映射。
> - 为何要 Learner？因为"从版式反推声明"是本质的逆向闭环。

## 本质竞品锚定记录
| 竞品 | 本质定义（AI 推断） | 与本项目核心差异 | 用户确认 |
|------|-------------------|----------------|---------|
| Pandoc | 用通用文档模型做格式互转 | 不内置"样式预设库"，且LLM易传错参数无白名单 | [x] 不是 |
| MarkText / Typora | 用所见即所得编辑器排 Markdown | 面向人交互，无 CLI/无逆向学习 | [x] 不是 |
| python-docx 直接调用 | 用 API 手写 Word 版式 | 无统一引擎、无样式复用、无 LLM 护栏 | [x] 不是 |
| **本项目 md2style** | 用声明式样式表 + 参数白名单做多格式映射 | 样式预设可复用 + 逆向学习 + LLM 无幻觉护栏 | [x] 确认 |

## 架构总览（第0级四层映射）

### 技术选型理由（由本质推导）
- **argparse（标准库）**：CLI 签名必须稳定可解析，LLM 拼接参数零歧义 → 满足"参数白名单"本质。
- **markdown-it-py**：生成标准 AST，比正则稳健，是 IR 的来源 → 满足"统一语义中间表示"本质。
- **python-docx / python-pptx / Jinja2+Pygments**：三种目标格式的权威读写器 → 满足"多格式精准映射"本质。
- **PyYAML**：声明式样式表的人类/LLM 共读格式 → 满足"声明式样式表"本质。
- **Poetry**：锁定依赖版本，保障固定脚本稳定性 → 满足"后端绝对固定"本质。

### 第0级四层映射表
| 四层 | 本项目对应 | 物理目录 | 依赖规则 |
|------|----------|---------|---------|
| 数据规范 | 全局常量、颜色/字体工具、IR 数据结构、日志 | `md2style/utils/`、`md2style/core/`（类型与IR定义） | 不依赖任何层 |
| 数据存储 | 样式预设 YAML、模板 dotx/html、系统字体探测 | `styles/`、`templates/`、`md2style/utils/fonts.py` | 仅依赖 core/ 抽象 |
| 数据流转（规则） | 样式引擎、MD 解析、逆向学习器 | `md2style/engines/` | 不直接依赖基础设施具体渲染实现 |
| 数据流转（编排） | 主控制器（路由子命令、参数白名单、流程编排） | `md2style/orchestrator.py` | 可依赖 engines/ 与 renderers/（接口） |
| 数据接口 | CLI 入口（argparse 子命令 convert/learn/preview）+ 本地 Web 界面（纯 Python） | `md2style/cli.py`、`md2style/interfaces/web/` | 可依赖 orchestrator/ |

> 注：素材原始目录已含 `engines/`、`renderers/`、`utils/`，本方案将"全局规范"收敛到 `core/`（IR 定义 + 常量），使第0级映射与 skill 标准坐标系对齐。

## 模块递归四层设计

### 模块 A：Style Engine（样式引擎，第1层）
- 本质（锚定父本质"声明式样式表取代自由描述"）：在统一映射引擎约束下，Style Engine 的本质是"**三层优先级合并 + 合法性校验的样式裁决器**"。
- 数据规范：`StyleConfig` 字典结构（headings/h1..h6: {size,color,font}; body: {font,line_height}）；优先级常量 DEFAULT < YAML < CLI。
- 数据存储：`styles/*.yaml`（只读加载）；系统硬编码兜底默认值在 `core/constants.py`。
- 数据流转：`load(yaml) → merge(cli_overrides) → validate(color/font/size)` 三步流水线；非法即抛 `StyleValidationError`。
- 数据接口：`resolve(style_name, cli_args) -> final_style`；`validate(style_dict)`。

### 模块 B：MD Parser（解析引擎，第1层）
- 本质（锚定父本质）：在统一映射约束下，MD Parser 的本质是"**Markdown → 与版式无关的统一语义 IR 的提取器**"。
- 数据规范：`IRNode` 类型（heading/paragraph/list/code/table + 元数据）；`IR` 为 `List[IRNode]`。
- 数据存储：内存（无持久化）。
- 数据流转：`parse(md_text) → 保留层级/列表嵌套/代码语言/表格对齐 → IR`；剥离所有原样式。
- 数据接口：`to_ir(md_text) -> IR`。

### 模块 C：Renderers（渲染器族，第1层）
- 本质（锚定父本质）：在统一映射约束下，Renderers 的本质是"**把 IR 节点按 final_style 精准写入目标格式的映射执行器族**"。
- 数据规范：`RendererBase` 抽象基类定义 `render(ir, final_style, output_path)`；各子类规范见子模块。
- 数据存储：输出文件（docx/html/pptx）；模板从 `templates/` 读取。
- 数据流转：`dispatch(output_suffix) → 选 renderer → 遍历 IR 逐节点写样式`。
- 数据接口：`render(ir, final_style, output_path)`（基类统一签名）。

#### 子模块 C1：Docx Renderer（第2层，锚定父本质"映射执行器"）
- 本质：在"IR→目标格式映射"约束下，Docx Renderer 的本质是"**段落/字符级样式注入器**"。
- 数据规范：依赖 `final_style['headings']`、`final_style['body']`。
- 数据存储：基于 `templates/word/*.dotx` 母版或空白文档。
- 数据流转：`遍历 IR → heading 写字号/颜色/字体 → paragraph 写正文样式 → 表格/代码块映射`。
- 数据接口：`render(ir, final_style, output_path)`。

#### 子模块 C2：Html Renderer（第2层）
- 本质：在映射约束下，Html Renderer 的本质是"**CSS 变量注入的自包含页面生成器**"。
- 数据规范：`--h1-color` 等 CSS 变量名空间。
- 数据存储：内嵌 CSS（无外部依赖）；`templates/html/base.html` 骨架。
- 数据流转：`IR → Jinja2 模板 + 注入 <style> 变量 → 代码块经 Pygments 高亮`。
- 数据接口：`render(ir, final_style, output_path)`。

#### 子模块 C3：Ppt Renderer（第2层）
- 本质：在映射约束下，Ppt Renderer 的本质是"**标题驱动幻灯片生成器**"。
- 数据规范：`final_style` 主题色/字体。
- 数据存储：`python-pptx` 母版。
- 数据流转：`每个 # 标题 → 新幻灯片标题；正文 → 占位符文本`。
- 数据接口：`render(ir, final_style, output_path)`。

### 模块 D：Learner（逆向学习引擎，第1层）
- 本质（锚定父本质"声明式样式表取代自由描述"的逆向）：Learner 的本质是"**从 Word 版式反推声明式 YAML 的提取器**"。
- 数据规范：输出结构同 `StyleConfig`，保证与 Style Engine 互通。
- 数据存储：写入 `styles/<name>.yaml`（含 `# 自动学习自: xxx.docx` 注释）。
- 数据流转：双模式——模式A（精准读标准样式 Heading1/Normal）→ 模式B（按字号/加粗聚类启发式）→ 写 YAML。
- 数据接口：`learn(docx_path, name) -> yaml_path`；`learn_heuristic(docx_path)`。

### 模块 E：Orchestrator（核心调度，第1层）
- 本质（锚定父本质）：在统一映射约束下，Orchestrator 的本质是"**子命令路由 + 参数白名单护栏 + 流程编排器**"。
- 数据规范：子命令枚举 `convert/learn/preview`；白名单参数集。
- 数据存储：无（纯编排）。
- 数据流转：`解析参数 → 白名单校验（未知参数报错）→ 调 Engine/Parser/Renderer/Learner`。
- 数据接口：`run(args)`；`dispatch_subcommand(args)`。

### 模块 F：CLI（数据接口层，第0级接口）
- 本质：在统一映射约束下，CLI 的本质是"**人类与 LLM 共用的固定入口（稳定可解析）**"。
- 数据规范：`argparse` 子命令定义（`-i/-o/-s/--h1-color` 等）。
- 数据存储：无。
- 数据流转：`argparse → 组装 args → 交 Orchestrator.run`。
- 数据接口：`main()`；子命令 `convert/learn/preview`。

### 模块 G：Web Interface（数据接口层，第0级·普通用户入口）
- 本质（锚定父本质"声明式样式表 + 参数白名单取代自由描述"）：在统一映射约束下，Web Interface 的本质是"**用浏览器表单采集参数、复用同一引擎的可视化入口**"（纯 Python 本地服务，不打包二进制）。
- 数据规范：表单字段与 CLI 参数一一对应（input 文件上传、style 下拉、微调滑块/色板）；输出同 Orchestrator 返回值。
- 数据存储：无（仅临时持有上传文件，用完即清）。
- 数据流转：`浏览器表单 → 组装 args(dict) → Orchestrator.run → 返回下载链接/预览`。
- 数据接口：`start(host, port)`（启动本地服务）；`handle_convert(form)`、`handle_learn(form)`、`handle_preview(form)`。
- 约束：界面层不含业务规则，仅采集与展示；共用 Orchestrator，与 CLI 等价。

## 验证方式
- **前置条件 P**：Python 3.10+ 与依赖已装（poetry install）；`styles/` 基线 YAML 存在。
- **后置条件 Q**：
  - 转换正确：convert 生成目标格式且结构正确（单元测试 + 文件可打开），全部通过。
  - 样式生效：CLI 覆盖参数写入偏差为 0（断言生成文件样式属性）。
  - 逆向学习：learn 生成的 YAML 可被 convert 复用，字段完整。
  - 无幻觉：传 `--unknown-param` 直接报错退出。
- **不变量 I**：
  - 接口稳定：convert/learn/preview 签名不变（接口测试）。
  - 默认样式不被破坏：内置 YAML 只读加载（校验）。
  - 输出兼容：生成文件可被对应软件打开（烟雾测试）。

## 项目愿景
- **短期**：跑通 convert（docx 优先）→ learn → preview 闭环，内置 3 套预设。
- **中期**：新增 PDF / LaTeX 渲染器（仅继承 base，不动其他模块）；流式渲染支持 >100 页长篇。
- **长期**：样式预设市场（用户共享 YAML）；LLM 函数签名自动从 CLI 生成，进一步收紧白名单。
